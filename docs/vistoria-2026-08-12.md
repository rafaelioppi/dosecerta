## Parte 1 — corrigido e em produção

### 1. Barra de conta do header sumia em qualquer tela ≤860px (crítico)
`responsive.css` ainda tinha o breakpoint set do site institucional antigo (menu hambúrguer,
grades de serviços/equipe/hero — tudo removido faz tempo). Uma regra órfã,
`.nav__extra-cta { display: none }`, continuava ativa e por coincidência é a mesma classe usada
hoje pela área de conta do header. Resultado: em qualquer celular/tablet em retrato, ninguém via
`Entrar`/`Cadastrar` (deslogado) nem `Calculadora`/`Admin`/`Sair` (logado) — só a logo.
**Fix:** removido o breakpoint set morto inteiro de `responsive.css`.

### 2. Header quebrava linha e ficava cortado em telas ≤480px
Ao reaparecer a barra de conta, logo + até 3 botões-pílula não cabiam numa linha só (~130px de
sobra em 320–414px) — o texto quebrava dentro de um header de altura fixa, ficando cortado.
**Fix:** abaixo de 480px o header vira 2 linhas (logo em cima, botões embaixo), com
`--header-height` ajustado.

### 3. Campo de senha do admin ("Adicionar usuário") ilegível em 320px
Input + botão de olho + "Gerar senha" numa linha só sobravam ~30px pro campo de texto.
**Fix:** abaixo de 480px, "Gerar senha" cai pra linha própria.

### 4. CSS morto na raiz de `public/`
`layout.css`, `variables.css`, `components.css` na raiz não eram referenciados por nenhum HTML
(todos usam `public/css/*.css`). Removidos.

### 5. Combobox de medicamentos "sumia" no celular (crítico — reportado ao vivo)
Em rede mais lenta, tocar/focar o campo de busca antes do fetch de `/api/medications` terminar
mostrava **"Nenhum medicamento encontrado"** em vez de indicar carregamento — parecia a lista
inteira quebrada. Reproduzido localmente simulando latência de rede.
**Fix:** estado de carregamento (`medsLoaded`) diferencia "catálogo ainda não chegou" de "não
achei nada pra esse termo"; mostra "Carregando catálogo…" e atualiza sozinho pra lista real assim
que o fetch termina, sem exigir novo toque.

### 6. Placeholder do peso parecia um valor real digitado (segurança/UX)
Não existia nenhum estilo de `::placeholder` no site inteiro. O exemplo `18,5` do campo de peso
herdava o mesmo negrito e tamanho de título do valor real — numa calculadora de dose pediátrica,
isso pode ser lido como um peso já preenchido.
**Fix:** `::placeholder` global com cor apagada e peso normal (`reset.css`); no campo de peso
especificamente, também reduzido de fonte de título grande/negrito pra fonte de corpo normal.

### 7. Login sem opção de mostrar a senha
Adicionado o mesmo toggle de mostrar/ocultar já usado no formulário do admin.

### 8. Admin não tinha como editar usuário nem resetar senha
A tabela de usuários só tinha criação — sem jeito de corrigir nome/papel ou resetar a senha de
alguém que esqueceu (a de medicamentos já tinha Editar/Excluir havia tempo).
**Fix:** `PUT /api/admin/users/:id` (nome/e-mail/papel/conselho editáveis; senha **opcional** — em
branco mantém a atual) + botão "Editar" na tabela, reaproveitando o formulário existente.

**Commits:** `42c80e1` (header/CSS morto), `eada48c` (combobox/placeholder/login/admin).
Ambos já passaram pelo deploy automático (`deploy.yml`) e o health-check em produção respondeu 200.
